# Known limitations

Honest list of what's missing or incomplete, so nothing here is mistaken for "done." Update this as gaps close.

## Not implemented

- **Style profile editing and portability**: profiles can be exported and imported as validated version-1 JSON files. Median shot duration and a user-set conventional color grade are editable and used for generated clips; original media remains untouched, and zero adjustments preserve source colors. Measured visual/audio reference values remain read-only; reliable beat/speech controls and other measured-signal-driven settings are not implemented.
- **Natural-language editing instructions**: the editing planner includes an offline rule-based parser, modular LLM adapters (Local Ollama, Cloud OpenAI with strict JSON schema), and alternative edit proposal generation (dynamic/cinematic/balanced). Basic editing is 100% offline-first. Source footage is split into non-overlapping ranges and never repeated to pad a target; the editor reports when available unique footage is too short.
- **Reference & audio analysis**: scene cuts, visual color/sharpness/flow metrics, tempo candidates, beat grid generation, cut-to-beat snapping, music sync scoring, embedded subtitle extraction (SRT/mov_text), and speech-activity caption timing are implemented. Visual/audio signals remain reviewable and non-destructive.
- **Reference similarity search**: references can be ranked by a bounded comparison of overlapping measured pacing, visual, and coarse audio signals. It is explainable and requires at least three shared signals; it does not require external cloud embeddings or FAISS index dependencies.
- **Model training & datasets**: Training Studio trains an offline logistic pacing-preference model from explicit feedback with stratified holdout evaluation against majority and chance baselines. Feedback datasets can be inspected via structured manifests with class balance and threshold validation. Model checkpoints support evaluation gating, promotion, and rollback.
- **Storage management**: Settings page displays multi-drive storage locations, free/total disk space, and provides a safe one-click cache purge for temporary render files and cached thumbnails.
- **Model Manager**: manages the one supported local pacing-preference model, including activation/rollback, SHA-256 checkpoint integrity, license/runtime metadata, CPU architecture, and host resource reporting. It does not yet acquire or manage third-party model formats/runtimes.
- **Preference learning**: explicit pacing feedback adjusts later pacing, clip thumbs-up/down votes add a small smoothed source-ranking offset, and users can save a clip's current color grade for later suggestions. The color preference uses a neutral prior and is tied to the selected source; it does not automatically learn across visually similar media. Feedback remains local to the selected project or style profile scope, and broader comparative evaluation remains unbuilt.
- **Generative AI features** (background replacement, video extension, etc.): not started.
- **Cloud AI providers**: no provider adapters exist; everything today is local/offline by construction (there's nothing to fail over from).
- **Reference library**: collections, tags, exclusion flags, basic filters, stable server-side pagination at 50 items per page, descriptive comparison for two selected references, measured-signal similarity ranking, and persisted stage-based analysis jobs with cancellation/restart recovery exist. Similarity is not semantic search and excludes references with fewer than three shared signals. Jobs report stages, not percentages. Cancellation checks run between analysis stages and visual/audio work; scene detection checks at detector callbacks, so a long scene with few/no detected cuts can delay cancellation.
- **Missing-file detection**: managed media and reference videos expose missing-file status and relink into managed storage; relinking a reference clears its old analysis and requires re-analysis. Directory batch import and full data-loss recovery scenarios need more testing.
- **Advanced planning and delivery**: moments are ranked using heuristic sharpness, exposure, and optical-flow features; there is no robust action/reaction recognition, shake classification, or duplicate detection. Per-clip exposure, contrast, saturation, warmth, and source-pixel crop positioning are editable; hue curves, scopes, LUTs, and shot matching are not implemented. Per-clip conventional FFmpeg deshake is available with blank edge handling; motion estimation can be imperfect and may leave black edges, which the quality scan may flag. Cut, fade-from-black, and simple video/audio crossfades are editable and rendered; transition style classification and more complex transition types are not implemented. Vertical 9:16, horizontal 16:9, and square export presets are selectable; arbitrary custom presets are not exposed in the UI. Basic timed text captions can be added and burned in with a system font, with an output-aspect and crop-aware 10% safe-area preview; automatic transcription and caption timing assistance remain unbuilt. The editor has bounded 50-step in-session undo/redo and persistent saved project checkpoints with timeline restore; individual undo operations are not persisted across restarts. The export quality report scans completed renders for sustained black intervals, sample peaks, EBU R128 integrated loudness, and true peak; it does not measure dialog-specific loudness, enforce a delivery target, or diagnose clipped source audio. The visible editing-brief parser supports a small set of duration/aspect/pacing/color constraints; it is not an open-ended LLM.
- **Analysis limits**: tempo and rhythmic onsets are review-only hypotheses, not beat tracking; speech-like ranges are coarse spectral heuristics, not voice activity detection or transcription. When explicitly requested, these coarse signals can influence source-moment ranking, but they do not align cuts to beats or guarantee dialogue preservation. Optional within-shot shake candidates use sparse global-flow reversals and can still be triggered by subject movement; they are not a reliable shake classifier or stability guarantee. OCR, speech transcription, framing/subject composition, action/reaction recognition, redundancy detection, and transition classification remain unbuilt.

## Implemented but not fully hardened

- **Windows packaging**: the refreshed `npm run package` build succeeds and includes the packaged Electron app, PyInstaller-frozen service, and bundled FFmpeg/FFprobe. `npm run make` reaches Squirrel packaging and creates the `.nupkg`, but the final `Setup.exe` stage is blocked in this restricted command sandbox because Squirrel cannot launch its bundled `7z.exe` (`Illegal System DLL Relocation`). The updated package's direct service launch/loopback health check is also blocked by sandbox socket permissions. An earlier packaged `.exe` was launched successfully and its backend was verified listening; the installer and service for the newest package still need a normal Windows environment check.
- **Auto-update outside a real Squirrel install**: `update-electron-app` correctly reports `Error: Can not find Squirrel` when the app is run from a plain `electron-packager` output folder instead of an actual Squirrel-installed location — this is expected and logged, not a crash. It hasn't been verified against a real Squirrel install (`Setup.exe` → installed app → update check) end-to-end yet.
- **Code signing**: not configured. Unsigned installers trigger Windows SmartScreen warnings.
- **Storage locations are not user-configurable**: the Settings page shows where things live and can open them in Explorer, but changing them (per spec section 30: configurable project/reference/media/model/dataset/checkpoint/export/cache/temp directories) isn't implemented — everything lives under Electron's fixed `userData` path.
- **Render progress**: the UI shows the current render *stage* (`encoding`, `complete`, etc.), not a numeric percentage — FFmpeg's own progress isn't parsed yet. This matches the spec's "show stage, not an invented percentage" rule, but a real percentage would be better UX.
- **Job cancellation**: the editor can request cancellation and the renderer terminates FFmpeg, but cancellation is polled at 100 ms intervals and Windows process-tree termination still needs end-to-end validation.
- **Full workflow verification**: focused processing tests pass. The full TestClient workflow stalls at the first request in this restricted Windows sandbox because AnyIO cannot create its asyncio socketpair; rerun the full workflow in a normal development environment before claiming end-to-end acceptance.

## Deliberate scope decisions

- **Non-generative AI editing**: AI features should analyze user footage and propose explainable, reversible edits. Face/body alteration, synthetic frames/people, and generative scene replacement are out of scope. Reframing uses source pixels or letterboxing.

## Product boundary for AI-assisted editing

The intended AI direction is analysis and editorial assistance over user-provided footage: shot and audio analysis, clip ranking, timeline suggestions, and explainable natural-language controls. Face or body alteration, face replacement, synthetic people, generated frames, and generative scene replacement are out of scope. Reframing must stay within source pixels or use letterboxing; proposed edits must remain reviewable and reversible.

- **Python 3.12 pinned** for the processing service venv, not whatever `python`/`py` defaults to. 3.14 was available on the dev machine but lacks prebuilt wheels for `opencv-python-headless` and other ML dependencies needed in later phases.
- **FFmpeg/FFprobe bundled via npm** (`ffmpeg-ffprobe-static`) rather than requiring a system install, so dev setup and eventual packaging share one source of truth for the binaries.
- **No large neural inference runtime is installed** (such as PyTorch or ONNX Runtime). The current preference model is a small offline logistic model implemented with existing numerical dependencies; larger runtimes remain deferred until a supported feature requires them.
